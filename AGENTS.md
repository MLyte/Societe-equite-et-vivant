# Agent instructions for Project Horizon

These instructions apply to the whole repository.

## Before working

Read these files before making any substantive change:

1. `.blueprint/context.md`
2. `.blueprint/ai-instructions.md`
3. `.blueprint/style-guide.md`
4. `.blueprint/decisions.md`

If the task targets a specific chapter, read only the relevant chapter and the files above. Do not load or rewrite unrelated files.

## Scope control

- Prefer the smallest possible change.
- Modify at most 2 to 4 files unless explicitly asked.
- Do not reorganize the repository without explicit instruction.
- Do not add new folders unless the user asks for them.
- Do not change the licence unless explicitly requested.

## Writing rules

- Write in French by default.
- Use a sober research-document tone.
- Avoid campaign language, slogans and ideological certainty.
- Distinguish facts, assumptions, hypotheses and open questions.
- Never invent sources. If a source is needed but unavailable, write `[source à vérifier]`.
- Do not present AI as intrinsically neutral.
- Do not present technocracy as a replacement for rights, justice or democratic control.

## Project doctrine

Project Horizon is not a political party, not a manifesto and not an authoritarian model.

It is a governance design project exploring how science, AI, democratic legitimacy and basic social guarantees can coexist under ecological constraints.

## Output expectations

For each task, provide:

1. the target files;
2. a minimal plan;
3. the changes made;
4. why the changes were made, in one or two sentences.

When editing Markdown, preserve existing structure unless there is a strong reason to change it.
